⌃
🔴 Critical — App cannot safely run in production without these
Session / JWT Authentication
No session middleware exists. After OAuth, the backend has no way to identify who is making API requests. Every route trusts a hardcoded local user.
Auth Middleware on API Routes
Calendar and AI routes are completely unprotected — anyone who can reach the server can read/write any user's events.
HTTPS / TLS Termination
Server currently runs plain HTTP. OAuth tokens and calendar data travel unencrypted. Need a reverse proxy (Nginx, Caddy) or platform TLS.
Google OAuth Redirect URI
GOOGLE_REDIRECT_URI is hardcoded to localhost:3001. Must be updated to production domain in both .env AND Google Cloud Console.
Secrets Out of .env Into Vault
Real GOOGLE_CLIENT_SECRET and API keys are in a plain .env file. Use platform secrets manager (Railway vars, Fly secrets, Vercel env) in production.
SQLite → PostgreSQL Migration
SQLite is single-file, not network-accessible, and has no connection pooling. Production needs PostgreSQL (Supabase or Neon recommended).
CORS Origin Lockdown
CORS must be restricted to the production frontend domain, not wildcard. Currently permissive for local dev.
Refresh Token Rotation
Access tokens expire in 1 hour. Need middleware to check expires_at and use refresh_token to get a new one automatically.
🟡 Important — Needed soon after launch
API Rate Limiting
No rate limiting on AI endpoints. A looping client could rack up hundreds of OpenAI API calls. Add express-rate-limit on /api/ai routes.
Input Validation / Sanitization
API body parameters go directly into SQL and Google API calls with no validation. Add Zod or express-validator.
Error Handling Middleware
Unhandled errors will expose stack traces to clients. Add a global Express error handler that logs internally and returns generic messages.
Structured Logging
No logging whatsoever. Add pino or winston to log requests, errors, and sync events with timestamps for debugging in production.
CI/CD Pipeline
No automated build or deploy. Add GitHub Actions to run lint + build on every push, and auto-deploy to Railway/Fly on merge to main.
Frontend Session Persistence
isAuthenticated state lives only in React memory — lost on page refresh. Need to check auth status via a GET /api/auth/me endpoint on load.
Database Backup Strategy
No backups configured. PostgreSQL providers (Supabase, Neon) have point-in-time recovery built in — enable it from day one.
🔵 Nice-to-have — Polish for a production-grade app
Test Suite (Vitest)
Zero tests currently. At minimum, unit-test the calendar sync transform, AI tool execution switchboard, and OAuth credential upsert logic.
Error Monitoring (Sentry)
Add Sentry to both frontend (React ErrorBoundary) and backend to get notified of production errors in real-time.
Multi-AI Provider Abstraction
Currently uses OpenAI. Wrap LLM calls in a provider interface so you can swap in Anthropic Claude, or route by capability, without changing app code.
Google Calendar Webhook (Push)
Currently sync is pull-only (manual or page-load). Use Google Calendar push notifications (webhooks) for real-time sync without polling.
Dockerfile + Container Deployment
No Dockerfile. Containerizing the app simplifies deployment to Railway, Fly, Render, or any cloud provider.
